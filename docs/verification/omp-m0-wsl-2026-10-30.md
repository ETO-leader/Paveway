## 新增实现与复现

```bash
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
.venv/bin/python examples/verify_omp_m0.py
.venv/bin/python examples/verify_omp_admission.py
# 仅新增压缩路径；退出 2 表示证实旁路，不是安全通过
.venv/bin/python examples/verify_omp_admission.py --case compact
```

`verify_omp_admission.py` 新增 `compact` 场景，先经同一子进程握手发送超长中文输入，等待真实回复，再执行 `/compact soft`。仅该实验将保留尾部预算设为 128 tokens，以保证确实存在可压缩内容；自动压缩仍禁用。输入使用 bracketed paste，未在准入前转送用户字节。验证普通请求没有中段标记且有裁剪说明，辅助请求重新包含中段，同时原生 Session 仍保存完整原文。JSONL 输出只记录长度、布尔观测和实验屏幕，不输出原始 provider payload。

探针现在自行记录实际 OMP 版本；`--admission-only` 排除 rename 和 compact 两个辅助推理反例。反例必须先有一次正常授权／请求，并正常退出，不能把启动失败、卡住或未经控制的请求计为成功反例。

新增 `RealCustomizationTests.test_native_template_expands_dynamic_capabilities_without_model`，读取真实 `get_state.systemPrompt`：自定义身份替换默认 Coding Assistant、原生模板展开动态 read 工具和 Skill 索引、bash 不出现、禁用工具／Skill 后相关能力消失，Skill 正文不内联。没有发出 prompt。`verify_omp_m0.py` 的隔离原生检查已加入此项。

## 实际结果与失败样例

初次全量运行因旧虚拟环境仍安装 0.19.1、缺少新增 PyYAML，43 项中有 36 项导入错误；不是功能通过。安装最新项目依赖后恢复正常，未删除测试或放宽断言。

第一次短文本压缩实验显示 `Nothing to compact (session too small)`，只有一次普通请求，超时后清理，退出 1；没有把它当作通过或安全证明。使用真正超长输入后进入有效压缩路径。

初次完整矩阵的归档比较也失败：实验输入以空格结尾，原生 composer 在提交时去掉尾部空白。隔离诊断确认 JSONL 中仍有完整用户消息；为避免把输入规范化当作正文丢失，fixture 增加明确的非空白尾标记，继续比较整段原文，未删除或放宽保留断言。之后 `original_input_retained=true`。

另一次全矩阵中，改用 bracketed paste 的短 `stall-context` 输入停留在 composer，`contexts=0` 后超时；这是没有到达待测边界，不能当作 IPC 不回应实验通过，原日志 `/tmp/paveway-refactor-admission-verified.log` 保留。现仅超长压缩输入使用 paste，短控制场景恢复原有按键输入。最终完整矩阵所有场景达到各自待测边界；不把这次复验描述成所有历史运行均稳定通过。

## 门槛决定与剩余工作

- **D4：失败**。`/rename` 已在本机重复证实旁路；手动压缩还会重新读取完整 Session，绕过普通 context 的裁剪。`compaction.enabled=false` 和空 methodOrder 只限制自动路径，不能禁止手动 soft override。
- **D5：原生模板能力的有限探针通过**，含动态工具／Skill 权限。统一 Prompt Composer、Persona 兼容迁移、规则及 MCP 全矩阵仍未实现／验收，不能把此探针称为 M4 完成。
- D1/D2 继续采用独立物理 Session 的后备设计，不实施共享接管；D3 前台严格 settled 锚点关闭；D6 自动投递关闭；D7 不宣称原生历史已被索引或同步。原后台 after-turn、CAS、去重和 uncertain 语义保留。
- 下一允许阶段仍为 M0。依据实施契约 B／D4 的「禁用受管 TUI 入口，保留旧 RPC/旧 TUI」，不安装受限启动器、不切默认入口、不提前创建依赖它的生产 schema。

安装源码线索：`session/session-maintenance.ts` 的手动 compact 选择 `compactMode.overrides.methodOrder`，随后通过 `convertToLlmForSideRequest` 产生摘要；`session/session-provider-boundary.ts` 仅普通 `convertMessagesToLlm` 调用 transformContext；`utils/title-generator.ts` 的 completeSimple 未传 session onPayload。虽然存在公开 `before_provider_request` Hook，也不能假定它覆盖标题或所有子 Agent 请求。

最小上游建议：使标题、手动压缩及其他辅助请求共同经过可拒绝的受信请求边界，并测试错误、重载及子 Agent 路径；再为共享接管及前台 settled 分别补证据。这是缺口说明，**未修改 OMP 或 Tijian 上游**。未测试真实模型、Browser、Subagent、Tijian 服务端写入授权或 Windows `tijian-mcp.exe`→WSL stdio 路径，WSL2 内运行 Linux 探针不等于这些验收。

Rollback tested：没有入口／schema 切换，无新数据库降级可演练；正常 native `/exit`、故障自有进程组清理及旧入口回归已执行。继续使用原 `./paveway.sh`／CLI 即为现有路径；不重写 Session，不重放 uncertain 请求。Commit SHA 在本轮交付中提供。
