# Draft upstream proposal: one launch-owned MCP server

**Status: blocked on official OMP v19.1.1.** This is a local proposal, not a supported flag or a patch. The audit below is against the [official release](https://github.com/can1357/oh-my-pi/releases/tag/v19.1.1) and its tagged source. No further rejection probes were run; the previous runtime evidence is in [Official OMP verification](./official-omp.md).

Paveway can run a Workflow’s Tijian server through native `.omp/mcp.json` at the Workflow Workspace. A conversation in another cwd needs that **one** validated definition without replacing native MCP discovery, copying project configuration, or allowing a different same-named definition to be selected first. The seam must run before credential lookup/refresh, `!command` execution, MCP daemon attachment, or server spawn. Removing tools after startup is too late.

## Proposed interface and input

**Choose a CLI input, `--managed-mcp-fd <fd>`, not an SDK wrapper.** Paveway launches an official binary and keeps its native TUI. Add an internal immutable value to the owned-session construction path, shared by interactive, RPC/RPC-UI and print launch paths. Do not expose the SDK’s manager replacement as the feature, add an extension callback, or add a second public SDK ingress in this change. An embedded SDK can later take the same single parsed value when there is a caller. This flag is Linux-only initially; reject it explicitly for ACP, standalone utility commands (including `omp read`), and unsupported platforms instead of ignoring it. With no flag, all behavior remains unchanged.

One already-open **sealed memfd**, passed by the caller, containing UTF-8 JSON such as:

```json
{"version":1,"name":"tijian","server":{"type":"stdio","command":"/opt/example/tijian-mcp","args":["--write-policy=none"],"cwd":"/work/workflow"}}
```

- Construct with `MFD_CLOEXEC | MFD_ALLOW_SEALING`, mode `0600`, and add `F_SEAL_WRITE | F_SEAL_GROW | F_SEAL_SHRINK | F_SEAL_SEAL` before handing it off. Open descriptors are inherited only by the intended launcher/OMP chain. The CLI accepts one decimal fd greater than 2 (reject duplicate flags), checks regular-file type, caller effective UID, mode and required seals on that descriptor, and uses bounded positioned reads, not a path reopen or stdin. Reject an absent, unsealed, empty, oversized, or truncated fd; close it on success or on rejection after taking ownership, before executable extensions, threads, MCP or subprocesses. Do not pass it on to OMP workers or tools. No file path, JSON or secrets in argv, environment, logs, crash details, config databases or session history. As with other local launch inputs, this does not protect against an already-authorized same-user debugger or arbitrary in-process code.
- Maximum 16 KiB, strict UTF-8, one object, unique JSON keys at every depth and no unknown fields. Require version `1`, a case-sensitive ASCII server name `[A-Za-z0-9][A-Za-z0-9_.:-]{0,99}`, and one `stdio` definition with absolute nonempty `command` and `cwd`. No NULs or unpaired surrogates in strings. `args` defaults to `[]`, at most 64 ordered strings of at most 2 KiB each. `env` is optional, at most 64 distinct `[A-Za-z_][A-Za-z0-9_]*` keys and values at most 2 KiB each; maps use own properties only. Managed values are **literal**; they do not expand `${...}`, look up bare variables, or execute `!command`. Optional `timeout` is a safe integer from 0 to 2,147,483,647 ms, `requestIdFormat` is `number|string`, `instructions` is boolean. No remote transport, auth, OAuth, header policy, provider, source path, or `enabled` field. Credentials should stay outside the input when possible. Parse and freeze a private copy once; `/mcp reload` never reopens the descriptor or rereads the Workflow definition.
- Assign internal provenance `managed-mcp`, scope `launch`, no writable path. An absolute `cwd` pins the child working directory to the owner’s chosen directory, independently of the active session cwd (OMP’s advertised MCP roots still follow its session). This authorizes only one row, not the source workspace, its files, instructions beyond that row’s policy, or unrelated providers. A later version may define a remote input separately; v1 does not guess how write-back, ambient credentials or redirects should work there.

## Resolution and collisions

Place the seam in `mcp/config.ts` over all provider-normalized observations **after source eligibility but before exact-name and cross-name dedupe**. Expose that internal stage from `capability/index.ts` without adding a callback to the public interface or registering a process-global provider. Keep the same ordering and the same native filtering for unrelated names.

1. Exclude native providers, extension IDs, project scope, and inactive profile sources exactly as discovery does. `mcp.enableProjectConfig: false` excludes native project rows; it does not make an explicit launch row a project row. Native importers retain their own layer-merging rules. Exact `disabledServers` or `disabledExtensions` for the managed name block it globally; a `disabledProviders` entry `managed-mcp` also blocks the launch row without permitting a same-name file fallback. `enabledServers` cannot override these exclusions. If the active-profile primary file exists but its allow/deny policy cannot be read or parsed, reject managed selection instead of silently assuming an empty denylist; no-flag degradation is unchanged. Non-string elements in an otherwise valid list are inert, just as they are in a native exact-string lookup.
2. Find the ordered bucket for the **exact raw name**. Native row suppression (`enabled: false` or built-in-transform drop, after force-enable) still claims that name when it belongs to the native priority winner. If that owner is suppressed, the managed name is disabled, not rescued by a lower row. If the owner is eligible, compare **every** eligible exact-name row, including lower-priority rows that would have lost the name. Ignore individually suppressed lower rows. An eligible row with malformed canonical connection inputs cannot prove equivalence and conflicts. Apply existing Exa/browser support filters to the selected name using native rules (without running auth or `!command`); if the selected launch row would be removed, report it as filtered, not active, with no raw-file fallback. Those two filters deliberately do not hide a same-name disagreement in the earlier comparison.
3. With no mismatch, select **one** launch row as the authority, with managed provenance; an equivalent native file is not a write-back target. Protect that exact name from generic alias dedupe, and never use it to suppress a different raw name. All other rows use native-to-native precedence and alias dedupe as before. `Tijian`, `tijian `, and `example:tijian` are not `tijian`; the model tool registry can still mint colliding aliases by its ordinary rules. This is a same-name admission check, not a policy against other servers or a general sandbox.
4. On disagreement, reject the managed launch before any MCP connection tasks are scheduled. Report `managed_mcp_conflict` with the managed name, each conflicting **provider/scope** (and an optional fixed recognized filename label), and only affected field labels such as `args`, `cwd`, `env` or `transport`. Never include values, arbitrary paths, individual environment key names, URLs, hashes of secret material, command output, or serialized provider rows. Use a typed sanitized result for runtime status and distinguish `disabled`, `filtered`, `conflict` and `selected`. A selected definition is not proof of a connected server.

### Equivalence for a v1 managed name

Compare canonical provider output, not original file spelling. Providers already expand native `${...}` and may root paths or translate a dialect. Use the same normalized shape for selection, testing, and startup; do not run `prepareConfig` or use either existing [`isSameMCPConnection`][coarse] or [`mcpIdentity`][host-identity] for the decision. The former is a cross-name dedupe heuristic and omits e.g. timeout/instructions/header policy. The latter is designed for daemon caching/sharing and intentionally ignores parts of the inherited environment.

| Field | Exact rule |
| --- | --- |
| Transport and endpoint | Omitted type is stdio only when there is a command and no URL. HTTP/SSE, conflicting endpoint fields, or any native auth, OAuth, headers or header policy are incompatible with this v1 row. Check the canonical candidate **before** conversion can discard contradictory fields. |
| `command` | Same absolute command string, exactly. No `PATH` search, realpath, symlink/inode matching, case folding or path rewriting. A non-absolute native command is not provably equivalent. |
| `args` | Absent or `[]` is the empty list. Otherwise compare length, order and each string literally, including empty strings. No app-specific flag equivalence: `[]` is not `['--write-policy=full']`; `['--read-only']` is not `['--write-policy=none']`. |
| `cwd` | `path.resolve(sessionCwd, candidate.cwd ?? '')`, compared with the normalized absolute managed cwd. This mirrors the [native stdio spec][server-spec], not the config file’s directory unless its provider already rooted it. No realpath; cwd absent at a different conversation directory is not equivalent. |
| `env` | Compare declared resolved literal maps by exact keys and values, ignoring map order; absent and `{}` are equivalent. Managed env is literal. Native keys qualify as literal only under `envPolicy: 'literal'` or when specifically listed in `envLiteralKeys` after provider normalization; reject any nonliteral declared key as unprovable, even when its text currently matches the managed value. This is conservative for bare variable lookup, dropped empty values and `!command`; do not evaluate any of them to prove equality. Compare declared env, not coincidentally equal inherited values. Both launch and test use the selected config and OMP’s existing inherited spawn-environment policy. [Native env expansion][expand-env] · [manager value resolution][manager-env] · [config value resolver][resolve-value] |
| Additional behavior | Normalize unset request-id format to `number`, unset instructions to `true`, and compare configured timeout exactly (absence remains a distinct native default; do not treat an environment override as proof of equivalence). Native `enabled` is handled by policy, not identity. Source metadata is not a connection input. |

The check covers configurations, not executable integrity. A binary, symlink target or an ambient credential may change independently. Keep normal host caching for unrelated MCP servers; make the managed stdio connection and its test **session-local and not shared with ordinary links** so the daemon cannot adopt a pre-existing same-identity child with different ambient inputs. Use the existing local host path with a private per-owned-manager host/identity namespace for the managed row; merely setting `mcp.shared: false` process-wide would change unrelated servers. A throwaway test uses a fresh managed test lease and no catalog-store answers.

## Management lifecycle and wiring

- **Startup and movement:** await the admission check before deferred TUI connection work and publish the selected generation before the owner admits input. A conflict or invalid explicit input must surface as a launch error rather than the ordinary `.mcp.json` warning. An explicit managed input must not bypass `enableMCP: false` or a restricted session that cannot own MCP; report a policy refusal rather than silently ignoring it. For live cwd movement, preflight the prospective cwd and policy before committing the move, retaining the old generation if it fails; use the same absolute managed child cwd. A Paveway host that requires managed availability must fail admission on disabled/filtered status rather than claim it inherited the server. Expose `{name, state}` (no definition) on the read-only extension session facade before its ready event and in native RPC session state. `selected` describes policy selection; connection readiness remains the normal MCP status.
- **Reload, plugin changes and live policy:** keep the immutable launch value on the owning manager, not in an options object that callers can omit. Resolve a new generation against current cwd, active profile, provider/extension state and normal filters on `/mcp reload`, `/reload-plugins` and project/browser policy reconciliation; invalidate the normal discovery cache on explicitly requested reload. Serialize changes with existing reconciliation. On late conflict or disable, cancel pending managed work, release that managed link and remove its tools, prompts and resource subscriptions before reporting the new state; never fall back to a raw duplicate or keep a previously authorized managed row active after a failed check. On a late conflict keep existing unrelated MCP connections and report that reload did not complete; a later clean reload may recover. Borrowed/subagent managers have no input of their own and follow the owner’s refreshed tools. Do not store or rediscover definitions in the daemon from the fd.
- **`/mcp test`, `/mcp reauth` and reconnect:** route the reserved name through one owner lookup pinned to the same published generation. A blocked or missing reserved name is a refusal, never an invitation to search files. TUI and headless tests use the resulting config, cwd and local test lease without mutating it. Reauth refuses managed stdio **before** any probe, auth storage mutation, browser action or config write; automatic OAuth and manual reconnect also must not select a raw definition for that name. `/mcp reload` on the owning headless dispatcher must call the owned runtime reload, not just refresh command names. Fence/cancel in-flight tests and pending reconnect work when their generation is invalidated; do not let a stale success restore tools. Edits to on-disk MCP definitions take effect at reload (or a native event that already triggers reconciliation), not through a competing, unsynchronized file lookup.
- **Other management commands:** list/status and `/extensions` show the managed source and its actual policy or connection state. `/mcp add`/`remove` on the reserved name refuse with launcher guidance; check before even an add-wizard connection test. Never create a user shadow or update even a matching project file. Enable/disable through either UI may update only the active-profile name lists and run reconciliation, never edit the supplied definition or bypass `disabledExtensions`, project policy or a conflict. Guard `MCPManager.connectServers` so incremental add/enable/dashboard callers cannot pass an arbitrary config for the reserved name around the owner’s resolver. Keep existing behavior for unrelated names and no-flag sessions. [Existing toggle writer][toggle-writer] · [dashboard incremental connection][dashboard-connect]

Minimal shape (illustrative, not an OMP patch):

```text
input = readAndFreezeSealedManagedStdioFdOnce(cli)
resolve(cwd, policy, input):
    rows = providerNormalizedRowsInPriorityOrder(cwd, policy)
    if input is absent: return ordinaryNativeResolution(rows, policy)
    bucket, others = partitionByExactRawName(rows, input.name)
    ordinary = ordinaryNativeResolution(others, policy)
    if nameDenied(input.name, policy) or nativeOwnerSuppressed(bucket, policy):
        return decision(ordinary, input.name, disabled)
    differences = eligibleUnsuppressed(bucket, policy)
        .compareAllAgainst(normalizeLiteralStdio(input, cwd))
    if differences: return decision(ordinary, input.name, conflict, redact(differences))
    if supportFiltered(input, policy): return decision(ordinary, input.name, filtered)
    return decision(ordinary, input.name, selected(input, source=launch))

startup: resolve; reject explicit-input errors/conflicts; publish; connect selected rows
reload/reconcile: resolve; invalidate prior generation; remove blocked managed link;
                  on conflict keep unrelated links; otherwise publish and apply next selection
test/reauth/reconnect: use owner decision for reserved name, never a raw-file fallback
```

## Acceptance matrix for an upstream change

Exercise public launch/mode behavior with isolated profiles, cwd and fixture servers. Count fixture spawns, secret-command executions, OAuth probes/writes and host attaches; a missing tool alone is insufficient evidence of safety.

| Case | Assertions |
| --- | --- |
| CLI input and descriptor lifetime | Valid sealed input works in interactive and native RPC/print without occupying stdin/stdout. Duplicate flag, wrong mode/owner/type/seals, missing fd, oversize/short read, invalid UTF-8/JSON, duplicate keys, unknown fields, bad name, remote type and relative required paths fail before discovery/auth. A child and a trusted extension cannot read the fd; no definition text in argv/env/logs/history. Reusing its fd number or editing the producer’s original data after admission changes nothing on reload. ACP and unsupported platforms reject the flag. |
| No input and no collision | No-flag fixtures retain native ordering, transforms, config errors and command behavior. A managed-only `tijian` and unrelated profile/project/imported tools all mount normally; managed child cwd is the Workflow cwd, not the conversation cwd. |
| Exact duplicates and hidden losers | Same normalized stdio definition in native primary, compatibility, standalone, imported and OMP extension-package sources selects one managed row and makes one initial managed connection. A differing low-priority same-name definition behind an equivalent higher-priority row still refuses. Parameterize `command`, arg order/mode, cwd, env map, auth, transport, timeout, request-id format and instructions. Capture safe provider/scope + field diagnostics and assert no connection, OAuth, or command-backed-value side effect occurred. |
| Normalization and aliases | Omitted vs empty args/env and explicit defaults described above coalesce; map order irrelevant. Relative/default cwd is resolved against the candidate session cwd; provider-rooted cwd and path aliases are checked by the specified rules, never guessed. Native nonliteral env (including `!marker`) conflicts and never executes, even when text matches. Different raw names, namespaced plugins and unrelated native-to-native alias dedupe remain independent. |
| Policy and profiles | Exact active-profile deny wins over force-enable, including a deny+allow pair; case/whitespace variants do not match. Project scope exclusion and disabled provider remove candidates before comparing; enabled provider/user opt-ins work as in native discovery. A suppressed winning row blocks selection; a suppressed lower row does not. Explicit force-enable changes per-row suppression but never restores policy-excluded sources. Project `disabledServers` and compatibility-file lists do not impersonate the primary active profile; malformed active-profile policy is not silently ignored with the flag. |
| Reload and races | Edit a lower-priority row, toggle live project config, change browser/extension eligibility, or reload plugins. A new conflict removes only managed tools/links from an already-running session and never attaches an alternative; after cleanup a subsequent reload restores one matching connection. Invalid prospective cwd leaves prior cwd/generation intact. Race a pending connect, test and reconnect against reload and assert no stale publish. Confirm no config file is modified and the input is not reopened. |
| Management surfaces and hosting | TUI/RPC/print tests target the selected definition with the same cwd and no cached result; disabled/conflicting names never fall back to a file. Reauth returns the stdio refusal with zero probes/auth writes. Reconnect respects the generation. Add/remove do not materialize it; enable/disable only alter authorized lists. An existing daemon server with matching coarse identity is not used by managed startup/test. Borrowed tool views drop and regain the managed tools with the owner. |

## Migration

1. Keep the existing Paveway cross-cwd refusal until an official version ships the seam and end-to-end launcher/management tests verify its contract. Detect the supported version/capability from the verified OMP installation, not user config, not a speculative flag, and not a silent downgrade. Keep the same-cwd native flow on older releases and for ordinary non-managed launches.
2. For a supported managed launch, read exactly the validated Workflow `tijian` stanza, preserve argument strings verbatim (including the legacy spelling), and set child cwd explicitly to the Workflow Workspace. Use a fresh sealed fd per launch through only the existing launcher/guardian chain, alongside—not inside—the private extension attestation input. A lease may be admitted only after OMP confirms it selected the managed definition and the existing Paveway attestation succeeds; do not confuse selection with readiness. Check the config revision at handoff, and release all new descriptors on failure/cancellation. [Paveway definition reader](../../src/oicoach_runtime/workflow_setup.py#L166-L208) · [launch code](../../src/oicoach_runtime/native.py#L196-L255) · [guardian fd handoff](../../src/oicoach_runtime/child.py#L71-L90)
3. Remove the launcher and UI cross-cwd rejection together only on the supported path. Never copy the source file into the target checkout/profile or migrate legacy definitions into a hidden global override. Paveway settings still author the Workflow definition; changing it requires a new launch. A genuine destination conflict is repaired explicitly by the user in its owning source, not by retrying without the flag or weakening Paveway’s selected permission. [Current launcher refusal](../../src/oicoach_runtime/native.py#L133-L146) · [current UI refusal](../../src/oicoach_runtime/bundled/paveway-management.mjs#L420-L430)
