# Tijian 业务工作流

## 先确认能力与证据

此 Skill 提供业务方法，不代表 Tijian 已连接。先检查当前会话实际提供的原生 MCP 工具及其说明；连接、权限、数据范围和具体输入输出以 MCP Server 的当前契约与调用结果为准。缺少能力或连接失败时说明限制，不猜参数、不编造题目或训练记录，也不将旧 CLI 桥接器的调用约定套用到原生 MCP。

## 题目与题面

- 先检索已收集的题目，确认题目标识、来源和任务范围。阅读已收集题面用 `problem_get`；初次收集会将题面持久化到本地。
- 缺少题目时使用 `problem_add`；缺少题面或用户明确要求刷新时使用 `problem_refetch`。普通阅读不要反复刷新。
- `网页示例/` 是解析器开发用 HTML 样本，不是运行时题面仓库，也不是收集题目的前置条件。
- 搜索结果用于定位，题面和记录用于支撑分析。跨年份或比赛比较时先检查覆盖范围，区分缺失数据与没有相关题目。

## 跨工具组织任务

按用户目标选择当前可用的题库、训练记录或其他业务能力，先读取相关事实，再形成建议。把题目、尝试记录及时间范围对齐；对推断标明依据，不把单次表现等同于长期能力。需要写入或更新业务数据时，先明确对象与变更范围，遵守当前权限；调用结果不确定时先核实状态，不盲目重复写入。

训练计划或记录与 Paveway 的唤醒事件是不同对象。写入业务计划不等于已经安排提醒；仅在用户需要且 Runtime 提供相应能力时单独安排。固定教学原则仍由 workflow 的 `coach.md` 模板负责；运行安全、身份、记忆和派发恢复规则仍由 Runtime 负责。本 Skill 不替代这些规则，也不维护 MCP 工具目录或 Schema。
